\chapter{Tools and Frameworks}
\label{c:tools}
%-------------------------------------------------------------------

\epigraph{\enquote{I believe that inside every tool is a hammer.}}{\emph{Adam Savage}}

This chapter describes the software stack, code organisation, and execution environment used in this thesis.
The aim is to give a precise and self-contained account of how the experiments are implemented and how they can be reproduced.

%----------------------------------------------------------
\section{Software stack}
%----------------------------------------------------------

All experiments are implemented in Python.
\Cref{tab:tools:stack} summarises the main libraries and their role.
The core models (NCA, Mixture NCA, and their extended and stochastic variants) are implemented with \texttt{PyTorch}~\cite{pytorch}, which provides automatic differentiation and efficient GPU execution for the repeated unrolling of the learned dynamics.
Numerical arrays and data handling use \texttt{NumPy} and \texttt{pandas}; visualisation uses \texttt{matplotlib}, \texttt{seaborn}, and \texttt{plotly} (the latter for interactive dashboards and for exporting static figures such as PNG or PDF).
Dependency versions are pinned in \texttt{requirements.txt} at the project root (e.g.\ \texttt{torch>=2.0.0}, \texttt{numpy>=1.24.0}), so that a fresh environment can be reconstructed for reproducibility.

Model training and evaluation are run from the command line via dedicated scripts; the results reported in this thesis are produced by these same pipelines.

\paragraph{Models (\texttt{mix\_NCA/}).}
The package contains the NCA and mixture-based models: \texttt{NCA.py}, \texttt{MixtureNCA.py}, and the extended variants \texttt{ExtendedNCA.py}, \texttt{ExtendedMixtureNCA.py}, \texttt{ExtendedMixtureNCANoise.py} (configurable neighbourhood size, stochastic rule selection, noise).
The tissue simulator in \texttt{TissueModel.py} defines the cell types (\texttt{ComplexCellType}: EMPTY, STEM, INTERMEDIATE\_1/2, DIFFERENTIATED\_1/2), the local update rules (death, survival, division, differentiation), and the \texttt{simulate} method.
\texttt{BiologicalMetrics.py} implements the comparison of generated vs.\ ground-truth distributions (KL divergence, chi-square, categorical MMD, tumour size, border size, spatial variance).
Training utilities (grid-to-channels conversion, \texttt{train\_nca\_dyn}, classification update network) are in \texttt{utils\_simulations.py}.

\paragraph{Data generation.}
Tissue histories are produced by the data-generation script at the project root.
The script instantiates the complex tissue model via \mbox{\texttt{TissueModel.create\_complex\_model\_example}} with a random number of initial stem cells per run, simulates each trajectory for a fixed number of steps, and saves the list of histories as a single \texttt{.npy} file.
\Cref{tab:tools:genhist} lists the script arguments; \Cref{tab:tools:dataset} specifies the dataset used for the main neighbourhood-size sweep in this thesis (see \cref{c:implementation}).

\paragraph{Experiment pipeline.}
The main entry point is in \texttt{experiments/}.
It loads a pre-generated \texttt{histories.npy}, splits into training and validation (e.g.\ 80\%/20\%), and for each requested neighbourhood size trains the Mixture NCA and Stochastic Mixture NCA with the same hyperparameters.
Curriculum learning is controlled by \texttt{--curriculum} and comma-separated options (\texttt{--curriculum\_time\_lengths}, \texttt{--curriculum\_epochs}, \texttt{--curriculum\_lrs}, \texttt{--curriculum\_update\_every}); early stopping is applied on training loss within each phase.
After training, the script evaluates each model at several rollout lengths (e.g.\ 25, 100, 500 steps) via \texttt{compare\_generated\_distributions} in \texttt{BiologicalMetrics}, and optionally generates rollout videos.
\Cref{tab:tools:expargs} summarises the main arguments; \Cref{tab:tools:outputs} describes the output layout.

\section{Reproducibility and artifacts}
%----------------------------------------------------------

Reproducibility is supported at three levels (\Cref{tab:tools:repro}).

\begin{table}[htbp]
  \centering
  \caption{Reproducibility mechanisms.}
  \label{tab:tools:repro}
  \begin{tabular}{@{}p{2.4cm}p{9.6cm}@{}}
    \hline
    \textbf{Level} & \textbf{Mechanism} \\
    \hline
    Data & Histories file is a serialised NumPy array; it can be re-generated with the data-generation script using the same \texttt{--n\_simulations}, \texttt{--n\_steps}, and \texttt{--seed}. \\
    \hline
    Randomness & The experiment script accepts \texttt{--seed}; when set, NumPy and PyTorch seeds are fixed at the start of the run. The seed and the absolute path to the histories file are stored in \texttt{summary.json}. \\
    \hline
    Configuration & Each run records the full training configuration in \texttt{summary.json} (neighbourhood size, epochs, time length, curriculum, checkpoint paths). Checkpoints and \texttt{biological\_metrics.csv} allow re-evaluation or further analysis without re-training. \\
    \hline
  \end{tabular}
\end{table}

A fully reproducible run from scratch can be obtained as in \Cref{tab:tools:steps}.
No additional tooling (e.g.\ containers or workflow engines) is required.

\begin{table}[htbp]
  \centering
  \caption{Steps for a fully reproducible run.}
  \label{tab:tools:steps}
  \begin{tabular}{@{}cp{10.5cm}@{}}
    \hline
    \textbf{Step} & \textbf{Action} \\
    \hline
    1 & Run the data-generation script with \texttt{--output\_path \textit{path}}, \texttt{--n\_simulations 300}, \texttt{--n\_steps 500}, \texttt{--seed 42}. \\
    2 & Run the experiment script with \texttt{--histories\_path} pointing to that file, \texttt{--seed 42}, and the desired \texttt{--neighborhood\_sizes} and \texttt{--curriculum} options. \\
    3 & Run the analysis scripts with \texttt{--results\_dir} (or equivalent) set to the same \texttt{output\_dir}. \\
    \hline
  \end{tabular}
\end{table}

\section{Compute and execution}
%----------------------------------------------------------

Training and evaluation can run on CPU but benefit from a GPU when available.
The experiment script supports \texttt{--device} with the values in \Cref{tab:tools:device}.
When set to \texttt{auto}, the code selects CUDA if available, otherwise Apple MPS (e.g.\ on M-series Macs), otherwise CPU.

\begin{table}[htbp]
  \centering
  \caption{Values of \texttt{--device} and their effect.}
  \label{tab:tools:device}
  \begin{tabular}{@{}ll@{}}
    \hline
    \textbf{Value} & \textbf{Effect} \\
    \hline
    \texttt{auto} & Use CUDA if available, else MPS, else CPU \\
    \texttt{cuda} & Use NVIDIA GPU (if available) \\
    \texttt{mps} & Use Apple Metal (M-series Macs) \\
    \texttt{cpu} & Use CPU only \\
    \hline
  \end{tabular}
\end{table}

Computational cost is dominated by the repeated unrolling of the NCA over many time steps (training windows and evaluation rollouts).
The experiments reported in this thesis were run on a single GPU or on CPU, with runtimes on the order of hours for a full sweep over multiple neighbourhood sizes and curriculum phases.
